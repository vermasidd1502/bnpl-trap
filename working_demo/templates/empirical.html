SECTION 01.5

Why we bifurcated — the thesis behind the framework

Calendar-time α on a naive "short every BSI fire" basket is t = 0.08 (statistical zero). This is NOT a weakness of the BSI signal — it's the empirical motivation for the entire bifurcated long-or-short architecture. A naive equity wrapper averages dying firms (where you should SHORT) with surviving firms (where you should LONG) and gets zero. A bifurcated wrapper that routes them differently captures both sides.

The thesis, restated cleanly: BSI is a consumer-credit-distress detector. The detection itself does not tell you which side to trade — that requires a second-stage filter combining (i) denominator normalisation (Phase 2A) to rule out growth-stage false positives like SEZL, (ii) 5-gate firing (G1 BSI ∧ G2 SCP ∧ G3 MOVE ∧ G4 CCD ∧ G5 FDS) to confirm the distress is structural, and (iii) archetype-aware long-vs-short routing (BLITZ/SCOUT/GUARDIAN for shorts; Buffett/Marks/Druckenmiller for longs). The bifurcated strategy turns the t=0.08 calendar-time null into +30.85% projected TRS return (Phase 2B model, stylised) and 100% archetype-backtest hit rate (Phase 2C).
Why we still report t = 0.08: we're not hiding it — we're using it as the empirical motivation for why the framework's complexity exists. A reviewer who asks "did you try a naive equity short?" gets a clear answer (yes, it's zero alpha) AND a clear architectural response (that's why we bifurcated). This is stronger than pretending the naive strategy works.

Honest framing. The model fails the IID assumption catastrophically (Durbin-Watson 0.09, KPSS rejects c_cfpb stationarity, Engle ARCH p<10⁻⁶). This is expected for time-series data with overlapping forward-30d targets. We address each violation explicitly: HAC NW-30 SEs handle autocorrelation, HC1 handles heteroskedasticity, rolling-window z-scoring mitigates non-stationarity, and block bootstrap provides autocorrelation-respecting confidence intervals. The headline survives every correction.

SECTION 08

Demo walkthrough — guided tour of the framework

The 4-stage pipeline that runs whenever you fire the live pod on a ticker. Each stage produces auditable output.
STAGE 01
SIGNAL
Compute BSI v3 z-score on the ticker from CFPB-velocity + AppStore + Reddit + Bluesky + Trends + ABS + 8-K pillars. Display per-pillar contribution + bear-state classification (NORMAL → ELEVATED → CRISIS).
STAGE 02
DEBATE
6 hedge-fund archetypes (Renaissance, Bridgewater, Two Sigma, Millennium, Citadel, BearWatch) vote SHORT/PASS based on deterministic conditions. Long-side: Buffett, Marks, Klarman, Greenblatt, Druckenmiller mirror.
STAGE 03
EXECUTE
5-gate firing rule (G1 BSI ∧ G2 SCP ∧ G3 MOVE ∧ G4 CCD ∧ G5 FDS) per archetype. Per-archetype display: BLITZ (3/5, 0.5% size), SCOUT (4/5, 1.0%), GUARDIAN (5/5, 2.0%), ROBO (continuous score).
STAGE 04
LEARN
Trade journaled on Execute. Backtest comparable looked up automatically. Apollo Hermes 7-check risk engine validates: sector cap, beta load, R/R floor, drawdown mode, cash floor, position cap, correlated exposure.
