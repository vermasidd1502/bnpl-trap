What each stage actually does

📥
Stage 1 · Ingest (BearWatch side)

Six free public data layers stream into a DuckDB warehouse: CFPB consumer complaints, Reddit, Bluesky (Tier A/B/C/D credibility-split), arXiv research, FRED macro, MOVE bond-volatility.

🧮
Stage 2 · BSI compute (BearWatch side)

For each of 25 firms, compute the 8-pillar weighted-z BSI daily. Apply the deterministic 11-state bear engine. Phase classifier blocks Phase-1 GROWTH events from progressing to FIRED_UP.

🔗
Stage 3 · HTTP webhook bridge

A new module — apollo_bearwatch_bridge.py — sits in the BearWatch repo. On every FIRED_UP transition, it serializes the bear payload and POSTs it to Apollo's /api/bearwatch/ingest.

🛡️
Stage 4 · Risk Engine verdict (Apollo side)

The ingest route enriches the bear payload with: live quote, sector exposure check, beta-adjusted size, drawdown-mode multiplier, cash-floor check, R:R ratio. Verdict (APPROVED / SCALED_DOWN / BLOCKED) returned in < 50ms.

📓
Stage 5 · Execute + journal + post-mortem

When the trader executes, the trade is auto-logged with foreign key to bearwatch_events.event_id. Realized P&L per BearWatch event accrues in a closed-loop reporting view.
